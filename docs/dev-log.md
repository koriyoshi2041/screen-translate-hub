### 第一次端到端运行（无界面）

`tools/dev/e2e.ts` 用真实的主程序核心、Python 采集（回放画面）、OCR、归一化和运行协调器，配模拟翻译源和记录显示端：

- 单次截图：6 个段落全部识别正确、合并正确，竞速完成，显示端收到 88 个事件，序号无缺口；含服务启动和 OCR 模型加载约 4.1 s；
- 持续屏幕：回放原页、滚动、换页、翻回四帧。待处理位如需求 04 第 3.2 节所述，第三帧在处理期间被第四帧替换；滚动的批次只识别 2 块区域、复用 5 段；翻回后滚出又滚回的段落命中译文缓存。

实测发现两处复用判定的问题，已修订 spec 04 第 4.5、4.6 节：

1. 内容滚到固定标题栏底下时，被挡住的一行仍在画面之内但不再一致，原写法要求一个位移对全部行成立，连带可见的行也定位不到，旧位置被送去识别，识别区域切过新位置上的文字，得到 "OnTversations." 这样的残缺原文，并在下一批被复用；
2. 相邻一行的下伸笔画落进这一行的方块，使一两个方块在任何位移下都不一致。

改为逐行定位，每行取过半方块一致的位移。定位只决定识别区域，复用判定仍要求全部一致。

### 桌面上的第一次运行

主程序（Electron 45）在桌面会话启动，开发时经 `--dev-control` 打开的本机控制端口驱动（`tools/dev/ctl.ts`），浮层被排除在采集之外，所以另取浮层页面最后渲染的一帧，与桌面截图合成后查看（`tools/dev/compose.ts`）；`--debug-capturable` 则让浮层可被采集，用于看真实层级。

**Electron 透明窗口在这台电脑上不显示。** 用 `tools/dev/electron-probe.cjs` 对照：不透明窗口正常，透明窗口无论 GDI 还是 Windows.Graphics.Capture 都采不到，`--use-angle=warp`、`d3d11-warp` 加 DirectComposition、`--disable-gpu` 都不行。`app.getGPUFeatureStatus()` 显示 `gpu_compositing: disabled_software`：远程软件的虚拟显示器上没有 GPU 合成，Chromium 的透明窗口依赖它。远程桌面、虚拟机、部分显卡驱动下用户也会遇到同样情况，所以没有当作本机问题绕过，而是改了实现：

- 浮层页面用离屏渲染（`webPreferences.offscreen`），每帧的 BGRA 位图经 `UpdateLayeredWindow` 推进一个原生分层窗口（`WS_EX_LAYERED`，逐像素透明，`koffi` 调用 Win32），不需要 GPU；
- 分层窗口照样可以 `WS_EX_TRANSPARENT` 穿透点击、`WDA_EXCLUDEFROMCAPTURE` 排除采集，实测两者都生效；
- 框选区域的窗口改为先截整屏、在不透明的全屏窗口里显示冻结的画面，用户在上面拖框，结果从这张截图里裁出。

接着在真实桌面上发现并修正：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 浮层页面有段落，画面上什么都没有 | 渲染器把根元素改成 `position: relative`，覆盖了页面的 `absolute; inset: 0`，根元素高度为 0 且 `overflow: hidden` | 渲染器只在根元素未定位时设定位，并按视图尺寸设根元素宽高 |
| 整屏浮层里的译文纵向错位约 6% | 窗口初始尺寸被限制在工作区（屏幕减任务栏），离屏页面只有 1366×720 | 页面加载后重新设置内容尺寸 |
| 开始持续翻译后任务栏沉到其他窗口下面 | 覆盖整块显示器的置顶窗口被系统当作全屏程序 | 浮层比显示器少一像素高 |
| 标题 "Release notes" 并进下一段 | 标题与正文的间距不到一行高，原规则只拆"两行都短"的标签 | 明显短于栏宽、下一行以新句开头时断开（spec 06 第 6 节 v1 补充） |
| Tk 窗口里相邻两段合成一段 | 段间距约 0.7 行高，小于 kg | 与本叶常见行距比较，多出 0.4 行高以上即断开 |
| 工具栏图标被识别成 "B"、"I"、"H1"、"++"，时钟、日期也被翻译 | 没有可译的词 | 不含字母或只有单个拉丁字母的段落不送翻译（需求 09 第 3.2 节） |
| "TubaWinUi3.exe - 系统警告" 盖上一块与原文一样的底板 | 译文只改了空格 | 译文与原文只差空白时不画 |
| 译文行首出现 "。" | 换行没有避头尾 | 闭合标点不放行首、开引号不放行尾 |
| 局部设置补丁冲掉了显示设置的其余字段 | 设置只做了浅合并 | 嵌套对象按键合并 |
| 跟随窗口时浮层盖住了别的置顶对话框，修正后又沉到目标窗口下面 | 插在置顶窗口之后会变成置顶；后台进程调用 `HWND_TOP` 成功但无效 | 目标在普通层最上时，先置顶再取消置顶（落在普通层最上），其余情况插在目标上方的窗口之后 |

持续模式在可控的测试窗口（`tools/dev/stage.py`）上的结果：首批 16 段竞速、7 段无词、4 段同语言；滚动 3 行后复用 22 段，只翻译新露出的 5 段；改写一段后命中缓存 5 段、新翻译 2 段；窗口移动后浮层跟到新位置。
