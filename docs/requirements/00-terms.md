# 术语表

本表列出需求文档中反复出现的术语。各文档首次使用某个术语时会再交代一次全称，之后固定使用表中的称呼。

## 处理相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 光学字符识别（OCR） | Optical Character Recognition | 从图片中识别文字的处理步骤。平台中由一个 OCR 节点完成，用户为每个节点选择一个 OCR 引擎 |
| 包围框（bbox） | Bounding Box | OCR 给出的文字所在区域。每个文字块对应一个包围框 |
| 归一化 | Normalization | 把不同 OCR 引擎的输出整理成统一格式：统一坐标、整理阅读顺序、合并行与段落，生成带唯一标识的翻译单元 |
| 段落 | Paragraph | 归一化后的翻译单元。一个段落可以由多个原始文字块合并而成，并保留这些原始包围框 |
| 翻译源 | Translation Source | 产生译文候选的一路来源，例如某个 AI 模型、某个服务器翻译接口或某个本地翻译引擎。同一个 AI 的流式输出和完整输出分别算作两个翻译源 |
| 流式源 | Streaming Source | 边生成边返回译文的翻译源。每次返回的是当前累计的译文，并带有递增的版本号 |
| 完整源 | Complete Source | 一次性返回整段完整译文的翻译源 |
| 候选 | Candidate | 某个翻译源针对某个段落返回的一份译文 |
| 竞速 | Race | 同一段落的多个翻译源并发执行，平台按用户设定的优先级和版本规则决定当前显示哪份候选 |
| 优先级 | Priority | 用户给所有启用的翻译源排出的先后顺序，用于决定候选之间能否互相替换 |
| 版本 | Version | 同一个翻译源对同一段落先后给出的候选的序号。流式源每输出一次累计译文，版本加一 |

## 工作流相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 工作流 | Workflow | 由输入、处理、输出节点及其连线组成的处理流程。用户可以创建多条工作流 |
| 节点 | Node | 工作流中的一个步骤，例如屏幕输入、OCR、翻译、AI、分支、显示输出 |
| 入口 | Entry | 用户触发工作流的方式，包括单次截图、持续屏幕、划词、图片问 AI |
| 模板 | Template | 平台为每个入口提供的默认工作流，用户可以修改或另建 |
| 执行位置 | Execution Location | 节点实际运行的设备，例如某台 Windows 电脑或 Docker 后台 |
| 操作面板 | Operation Panel | 日常使用的界面：选择入口、来源、工作流和参数后直接运行 |
| 节点编辑器 | Node Editor | 修改工作流结构的画布界面 |

## 运行相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 运行 | Run | 用户点击开始到停止之间的一次完整执行。每次开始都会建立新的运行 |
| 触发方式 | Capture Trigger | 决定持续屏幕何时截屏的方式。首版为按用户设定间隔的定时触发，后续加入鼠标点击、键盘操作和快捷键触发 |
| 批次 | Batch | 一次截图或一张确认发生变化的屏幕画面，以及围绕它进行的 OCR、归一化和翻译 |
| 待处理位 | Pending Slot | 持续屏幕运行中暂存下一张待处理截图的位置，最多保存一张，新截图会替换旧截图 |
| 节点超时 | Node Timeout | 单个节点一次调用允许的最长时间 |
| 批次总时限 | Batch Deadline | 一个批次从开始处理到结束允许的最长时间 |
| 显示快照 | Display Snapshot | 某一时刻显示端上的完整画面：底图、包围框位置、选中的译文和显示设置 |
| 显示设置 | Display Settings | 亮度、字号、图层显隐等只影响绘制效果的设置，调整时不重新触发 OCR 或翻译 |

## 设备相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 主人 | Owner | 一套部署唯一的管理账号，管理自己的多台设备 |
| 来源 | Source | 开启了屏幕共享、可以被观看的一路 Windows 画面 |
| 观看端 | Viewer | 登录后观看某一路来源的浏览器，包括手机和电脑 |
| 后台 | Backend | 以 Docker 部署的统一服务端，负责账号、设备连接、跨设备中转和服务器侧处理 |
