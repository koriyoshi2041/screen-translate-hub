# 产品需求

本文描述平台面向谁、以什么形态部署、提供哪些功能入口，以及结果如何展示和保存。工作流、竞速翻译和生命周期的细则分别见 [工作流](02-workflow.md)、[OCR 与竞速翻译](03-ocr-and-translation-race.md) 和 [运行与生命周期](04-run-lifecycle.md)。

## 1 产品定位

平台是一个公开发布的自部署工具。其他用户自行安装和部署，因此安装、升级、兼容性和配置体验都属于首版需求。

平台的主线场景是持续屏幕翻译。用户在 Windows 上选定窗口或区域后，平台持续识别画面中的文字，把译文叠加在原文位置，并同时在本机和网页上展示。

首版持续屏幕翻译的效果验收以文档、漫画和软件界面为准。这类画面通常会停留一段时间，验收重点放在三点：

- 文字识别准确；
- 同一画面上的译文稳定，不反复跳动；
- 翻页或界面切换后，译文及时更新到新内容。

围绕同一套处理能力，平台还提供以下功能：

- 单次截图翻译；
- 划词翻译与划词询问 AI；
- 截图或当前画面询问视觉 AI；
- 多设备通过网页观看经过翻译或 AI 加工的屏幕：网页显示源设备的画面，并在相应位置叠加译文或 AI 注释。

## 2 使用者与部署形态

### 2.1 使用者

一套部署服务一个主人，主人可以接入自己的多台设备。账号、登录、设备接入和观看规则见 [账号、设备与共享](05-accounts-devices-sharing.md)。

### 2.2 后台部署

后台以 Docker 一次部署完成，部署后即可使用账号、设备连接、跨设备中转和服务器侧的 OCR、翻译与 AI 处理。OCR、翻译等能力以接口区分，部署时不要求为每项能力单独建立容器。

首版必须同时提供两种部署方式，并分别给出完整的说明与配置：

| 部署方式 | 网络条件 | 首版需要提供的内容 |
| --- | --- | --- |
| 公网服务器 | 有域名或公网地址 | 服务器部署方案；Windows 与观看端主动连接该服务器 |
| 家庭电脑或 NAS | 可以没有公网入口 | 家庭后台的部署方案，以及让异地设备访问家庭后台的公网接入方案 |

首版直接支持互联网异地连接。例如，手机使用移动网络时，也能登录部署在家中或云端的后台并观看画面。

### 2.3 Windows 独立使用

Windows 客户端配置好本机引擎后，可以在没有 Docker 后台的情况下独立工作。独立工作时可用的功能包括截图、OCR、翻译、划词问 AI 和图片问 AI，其中 AI 使用本机已配置的语言模型和视觉模型服务。

跨设备观看和需要后台节点的工作流必须连接后台。

## 3 客户端与平台

| 客户端 | 首版职责 |
| --- | --- |
| Windows 桌面端 | 截图、划词、持续屏幕采集；本机持续翻译覆盖层、截图浮卡、划词浮卡、对话面板、鼠标旁 AI 提示；本机 OCR 与翻译；向后台开放用户选定的本机服务 |
| 网页端 | 在电脑或手机浏览器中运行；选择来源并观看经过翻译或 AI 加工的画面、发起 AI 对话、查看历史记录、管理平台 |

Android 首版只作为网页端的浏览器使用，不提供原生客户端，也不采集或翻译 Android 自身的屏幕内容。

桌面端首版面向 Windows。桌面程序需要能够扩展到其他桌面操作系统，具体支持时间列入 [待定事项](open-questions.md)。

Windows 桌面端首版最低支持 Windows 10 2004 版。平台自己的覆盖层、浮卡和鼠标旁提示必须排除在屏幕采集之外（见 5.6），Windows 从这个版本开始提供这项能力：窗口通过 `SetWindowDisplayAffinity` 设为 `WDA_EXCLUDEFROMCAPTURE` 后，不再出现在屏幕采集中。更早的版本把这个取值当作 `WDA_MONITOR` 处理，窗口在截图中成为一块没有内容的区域，挡住下面的原文。

## 4 功能入口

平台有四个功能入口。每个入口绑定一条工作流，平台为每个入口提供默认模板，用户可以修改模板或绑定自建的工作流，规则见 [工作流](02-workflow.md)。

| 入口 | 用户操作 | 默认处理 | 结果展示 |
| --- | --- | --- | --- |
| 单次截图 | 框选屏幕区域 | 截图 → OCR → 归一化 → 竞速翻译 | 可移动的截图浮卡，原图与译文分层 |
| 持续屏幕 | 选择来源范围并开始 | 采集 → 变化检测 → OCR → 归一化 → 竞速翻译 | Windows 本机覆盖层与网页同时持续展示 |
| 划词 | 选中文字 | 翻译或询问 AI | 浮卡，可以继续追问 |
| 图片问 AI | 选择截图或当前画面 | 视觉 AI | 对话面板，支持多轮问答 |

### 4.1 单次截图

用户框选屏幕区域后，平台对这张截图执行 OCR、归一化和竞速翻译。结果显示在一张可以拖动的浮卡中，原图和译文是两个图层，用户可以切换查看。手动截图及其译文自动进入历史记录。

### 4.2 持续屏幕

持续屏幕支持两种范围选择方式，首版都要提供：

- 固定范围：用户选定整个屏幕、某个窗口或某个固定区域，开启后对该范围持续采集；
- 跟随活动窗口：开启后自动跟随用户当前使用的窗口。

两种方式之间的切换规则列入 [待定事项](open-questions.md)。

开启后，平台按用户选择的触发方式截屏，只有确认画面发生变化时才进入 OCR，直到用户停止。截屏频率不写死：首版提供按用户设定的间隔定时截屏，后续版本加入鼠标点击、键盘操作和快捷键触发，用户操作一次就截屏翻译一次。

相邻两个批次的画面往往大部分相同。新批次中原地未变或整体平移的段落，直接沿用上一批次的识别结果和译文，平台只对变化的区域重新识别和翻译；重新识别后原文与先前某个段落相同时，直接使用译文缓存中的译文。这样画面上没有变化的译文保持稳定，也不重复消耗翻译调用。

处理节奏、触发方式、批次、段落复用和停止规则见 [运行与生命周期](04-run-lifecycle.md)。

### 4.3 划词

用户在任意软件中选中文字后，可以选择翻译或询问 AI。已经取得的文字直接进入翻译或 AI，跳过 OCR。结果显示在浮卡中，用户可以在浮卡内继续追问。

### 4.4 图片问 AI

用户选择一张截图或当前画面，把图片直接发送给视觉 AI，在对话面板中多轮问答。这个入口的默认模板跳过 OCR，由视觉 AI 直接理解图片。

图片问 AI 可以从两端发起：

- 在 Windows 上发起时，图片来自新截取的截图或当前屏幕，对话在 Windows 对话面板中进行；
- 在网页端发起时，图片来自正在观看的画面或历史记录中的截图，对话在网页对话面板中进行。

在 Windows 上发起、工作流的全部节点都绑定在本机时，这个入口可以脱离后台使用。

## 5 展示方式

### 5.1 原画面与译文分层传输

平台传输的原画面不烧入译文。翻译结果单独传输，并携带每段文字的位置以及它对应哪一张画面。每个显示端自己把画面、包围框和译文组合起来绘制：网页端把译文作为叠加层，按位置信息绘制在原画面上方；Windows 本机覆盖层不需要画面，直接把译文绘制在实时屏幕上。

这样分层有四个直接好处：

- 调整亮度、字号或图层显隐时，只需重新绘制，不必重新执行 OCR 或翻译；
- 屏幕尺寸不同的观看端可以按各自的缩放比例重新排布文字；
- 每个显示端可以使用自己的显示设置，互不影响；
- 用户随时可以切回原画面，原画面本身没有被修改。

### 5.2 持续屏幕的叠加效果

译文绘制在原文所在的位置。当前版本的展示效果是：整幅原画面降低亮度，译文保持正常亮度，以此突出译文。亮度可以调节，用户也可以切回未经处理的原画面。

Windows 本机覆盖层是盖在实时屏幕之上的透明图层，只绘制暗化层和译文，不绘制截图。用户透过覆盖层看到的始终是实时画面，鼠标和键盘操作穿过覆盖层，直接作用于下面的窗口。

译文是对屏幕内容的补充，持续屏幕的显示不要求与屏幕实时同步。画面变化后，覆盖层在下一个批次开始时才更新；在此之前，旧译文留在原来的位置，与已经变化的画面错开。更新的方式见 [运行与生命周期](04-run-lifecycle.md) 3.6。

展示效果按具体功能描述和配置，不划分高低档位。首版只实现降低亮度；半透明遮罩、高斯模糊等效果可以作为后续新增的具体效果。

### 5.3 浮卡与 AI 提示

截图浮卡可以在屏幕上自由移动，原图和译文分层显示。划词浮卡显示译文或 AI 回答，并可以继续追问。

Windows 本机还提供鼠标旁的 AI 提示：AI 的评价或回答直接显示在鼠标指针附近。

### 5.4 观看端的画面

观看端一次只显示一路来源，用户在界面中选择要观看哪一路。同一路来源可以被多个设备同时观看。来源的构成规则见 [账号、设备与共享](05-accounts-devices-sharing.md) 4.3。

同一条工作流的所有显示端看到同一份翻译结果。同一路来源的所有观看端共用该来源的翻译目标语言。

持续屏幕运行时，观看端默认显示当前正在处理的那张截图，以及与它对应的包围框和译文，这样文字层始终与底图匹配。观看端同样不要求与源电脑的屏幕实时同步。画面刷新策略保留配置能力，其他可选策略的具体内容列入 [待定事项](open-questions.md)。

### 5.5 显示设置

亮度、字号、图层显隐等显示设置由每个显示端各自保存。一个显示端调大字号或切回原画面，只改变它自己的绘制，不影响本机覆盖层和其他观看端。手机屏幕小，需要比电脑更大的相对字号，各端分开设置后都能看清。

显示设置不触发 OCR 和翻译，各端分开保存不增加任何处理成本。各显示端共享的只有翻译结果。

### 5.6 平台窗口不进入采集

截图、持续屏幕和图片问 AI 采集到的画面，不包含平台自己绘制的覆盖层、浮卡和鼠标旁提示。

本机覆盖层直接盖在被采集的画面上。如果它进入采集，下一张截图就会带上上一批次的译文：变化检测把平台自己的绘制当作画面变化，OCR 再去识别这些译文，形成循环。浮卡和鼠标旁提示停留在采集范围内时，同样会挡住原文并被识别。

## 6 AI 交互

AI 问答由用户主动发起。用户可以把以下内容交给 AI：

- 选中的文字；
- 截图或当前画面；
- 某段译文或某次翻译结果。

文字问题交给语言模型，图片问题交给视觉模型。对话在 Windows 的划词浮卡和对话面板，或者网页对话面板中进行，支持多轮追问。AI 服务由用户配置，可以是外部 AI 服务，也可以是本机或服务器上运行的模型。

AI 也可以作为翻译源参加竞速翻译。这时 AI 随工作流的运行自动调用，规则见 [OCR 与竞速翻译](03-ocr-and-translation-race.md)。

## 7 多语言

平台从第一版起支持多语言，不预设重点语言对。以下三类语言分别配置：

| 配置项 | 作用范围 |
| --- | --- |
| 界面语言 | Windows 客户端和网页端的界面文字 |
| OCR 识别语言 | OCR 引擎识别画面文字时使用的语言 |
| 翻译源语言与目标语言 | 翻译的输入语言和输出语言，合称语言对 |

OCR 引擎和翻译源各自声明支持的语言，可选的语言列表由引擎能力决定，用户配置时在这个范围内选择。

参加同一场竞速的翻译源必须输出同一种语言，否则段落在替换时会从一种语言换成另一种语言。因此语言对设在竞速节点上，由参加竞速的所有翻译源共用，可选范围是这些翻译源都支持的语言；不经竞速的单个翻译节点自带语言对。语言对属于运行开始时固定的配置。

OCR 识别语言可以手动指定，也可以交给引擎自动检测。

归一化需要处理不同的书写方向，包括横排与竖排。译文排版需要处理译文比原文长、所选字体缺少某些字符时改用其他字体，以及不同书写方向的情况。

多语言的效果验收需要选定一组具体的语言测试样本，样本范围列入 [待定事项](open-questions.md)。

## 8 历史记录

以下内容自动保存到历史记录：

- 用户手动截取的截图；
- 这些截图的识别结果与译文；
- AI 对话，以及用户在对话中主动发送的图片和附件。

持续屏幕运行时连续采样的画面不进入历史记录，平台也不录制屏幕。

历史记录需要提供列表查看、容量上限和清理功能。容量上限与清理规则，以及 Windows 独立使用时产生的历史如何与后台合并，列入 [待定事项](open-questions.md)。

## 9 硬件要求

平台在普通 CPU 上即可使用。基础 OCR 可以在 CPU 上运行，翻译和 AI 可以连接外部服务。

GPU 是按引擎提供的可选加速。每个 OCR 引擎或翻译引擎声明自己是否支持 GPU，用户在配置该引擎时决定是否启用。

## 10 一次完整使用

1. 选择截图、持续屏幕或划词入口。
2. 选择来源、工作流以及该工作流需要的参数。
3. 在 Windows 上开始运行；需要跨设备观看时，在 Windows 上主动开启共享。
4. 在手机浏览器中登录，从来源列表中选择一路观看。
5. 选择文字、截图或翻译结果，主动向 AI 追问。
6. 暂停或停止。手动截图、译文和对话进入历史记录，连续采样的画面不保存。
