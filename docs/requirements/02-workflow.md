# 工作流

工作流（Workflow）是由输入、处理、输出节点及其连线组成的处理流程。截图、持续屏幕、划词和图片问 AI 这四个入口都通过工作流完成处理，用户可以修改每一步用什么引擎、在哪台设备上执行、数据传给谁。

本文规定工作流的使用方式、节点种类、执行位置和跨设备数据流向。OCR 归一化与竞速翻译的规则见 [OCR 与竞速翻译](03-ocr-and-translation-race.md)，运行期间的生命周期见 [运行与生命周期](04-run-lifecycle.md)。

## 1 使用方式

日常使用操作面板：选择入口、来源、工作流和参数后直接运行。需要修改流程结构时，再进入节点编辑器。

用户可以创建多条工作流，并为截图、持续屏幕、划词、图片问 AI 分别绑定其中一条。平台为每个入口提供开箱即用的默认模板，模板可以修改，也可以复制后另存为新的工作流。

节点编辑器在 Windows 本机界面和网页端之间如何分工，列入 [待定事项](open-questions.md)。

## 2 默认模板

### 2.1 单次截图

截图输入 → OCR → 归一化 → 多个翻译源并发 → 竞速 → 截图浮卡。

浮卡中原图与译文分层显示。

### 2.2 持续屏幕

屏幕输入 → 变化检测 → OCR → 归一化 → 多个翻译源并发 → 竞速 → 结构化译文输出 → Windows 本机覆盖层与网页显示。

变化检测放在 OCR 之前，画面没有变化时不重复执行 OCR。画面有变化时，新画面与上一批次的画面比对：OCR 只识别变化的区域，原地未变或整体平移的段落沿用上一批次的结果，命中译文缓存的段落不再竞速。规则见 [运行与生命周期](04-run-lifecycle.md) 3.5。

### 2.3 划词

选中文字输入 → 翻译或 AI → 浮卡。

文字已经取得，模板跳过 OCR 和归一化。浮卡支持继续追问。

### 2.4 图片问 AI

截图或当前画面输入 → 视觉 AI → 对话面板。

图片直接交给视觉 AI，模板跳过 OCR。对话面板支持多轮问答。

### 2.5 修改模板的例子

模板只是起点。用户可以按需调整，例如：

- 把单次截图的图片直接送给视觉 AI，跳过 OCR；
- 在单次截图模板中给 OCR 结果加一条分支，同时送给 AI 做摘要；
- 把翻译源从一个本地引擎增加到本地引擎、服务器翻译和 AI 三个，形成竞速。

## 3 节点

### 3.1 节点种类

输入、处理和输出都表现为可以连接的节点。

| 类别 | 首版包含的节点 |
| --- | --- |
| 输入节点 | 屏幕输入、截图输入、选中文字输入、图片输入 |
| 处理节点 | 变化检测、OCR、归一化、翻译、竞速、AI 对话、视觉 AI |
| 流程节点 | 分支：把同一份数据同时送往多条后续路径；条件分支：按条件选择后续路径 |
| 扩展节点 | 自定义 HTTP 接口节点，由用户填写接口地址和参数，接入平台未预置的服务 |
| 输出节点 | 截图浮卡、划词浮卡、本机持续翻译覆盖层、网页显示、鼠标旁 AI 提示、Windows 对话面板、网页对话面板、保存到历史记录 |

首版的节点种类为预置节点加自定义 HTTP 接口节点，脚本节点留待以后。完整的节点清单和连线上传递的数据格式在 spec 阶段确定。

### 3.2 输入输出受设备能力约束

输入节点和输出节点只能放在实际具备该能力的设备上：

| 节点 | 可放置的位置 |
| --- | --- |
| 屏幕输入、截图输入、选中文字输入 | Windows 桌面端 |
| 图片输入 | Windows 桌面端：新截取的截图或当前屏幕；网页端：正在观看的画面或历史记录中的截图 |
| 截图浮卡、划词浮卡、本机持续翻译覆盖层、Windows 对话面板、鼠标旁 AI 提示 | Windows 桌面端 |
| 网页显示、网页对话面板 | 网页端 |

例如，网页观看端无法作为屏幕输入，Docker 后台无法弹出 Windows 浮卡。

### 3.3 自定义 HTTP 接口节点

自定义 HTTP 接口节点会把数据发送到用户指定的地址。节点上需要明确显示三项内容：请求从哪台设备发出、发往哪个地址、发送哪些数据。

## 4 执行位置与服务绑定

### 4.1 处理节点逐个绑定服务

OCR、翻译源、AI、自定义 HTTP 接口等处理节点，由用户逐个选择在哪台设备上执行。可选的位置包括本机 Windows、Docker 后台，以及其他已经向后台开放了该项服务的 Windows 设备。

其他 Windows 设备只有在用户逐项开放某项服务后，才会出现在该服务的可选位置中，规则见 [账号、设备与共享](05-accounts-devices-sharing.md)。

### 4.2 归一化与竞速在同一处完成

归一化、竞速，以及竞速结果的汇总与分发，在同一个位置完成。用户在工作流中为它们选择一个位置，例如本机 Windows 或 Docker 后台，这几步始终在同一台设备上执行。

OCR 和各个翻译源分布在哪些设备上，都不影响这一点：它们的结果统一送到这个位置，由这里决定每个段落显示哪份译文，再发给所有显示端。

持续屏幕中，段落复用的判定和译文缓存也在这个位置完成。变化检测给出新画面中变化和平移的区域，这里结合上一批次的段落和竞速结果，决定哪些段落沿用旧结果。

### 4.3 绑定的例子

一条持续屏幕工作流可以这样绑定：

| 节点 | 执行位置 |
| --- | --- |
| OCR | 电脑 A 上的 OCR 服务 |
| 归一化与竞速 | 电脑 A |
| 翻译源 1 | 电脑 A 上的本地离线翻译 |
| 翻译源 2 | Docker 后台 B 上的 AI 翻译 |
| 显示输出 | 电脑 A 的本机覆盖层，以及网页观看端 |

### 4.4 服务不可用时不自动替换

工作流绑定的服务不可用时，该节点按失败或超时结束，平台不会自动改用本机服务或其他引擎。

其他节点能否继续运行，取决于它们是否依赖这个节点。以 4.3 的绑定为例，后台 B 断连后：

- 翻译源 2 结束；
- 翻译源 1 和竞速都在电脑 A 上，继续为每个新批次更新电脑 A 本机覆盖层上的译文；
- 网页观看端经后台取得画面和译文，后台断连期间收不到更新。

如果同一条工作流把归一化与竞速放在后台 B，后台断连后竞速无法进行，电脑 A 本机覆盖层上的译文也随之停止更新。

### 4.5 是否需要后台在线

全部节点都绑定在本机的工作流，可以脱离 Docker 后台运行。包含后台节点或其他设备节点的工作流，需要后台在线才能调用这些节点。

## 5 跨设备数据流向

### 5.1 画布需要表达的内容

用户在节点编辑器中构建工作流时，必须能看清每一步的数据从哪里来、交给谁、结果回到哪里。

| 内容 | 用户能明确看到和指定的信息 |
| --- | --- |
| 执行位置 | 节点在哪台电脑或哪个后台上运行 |
| 数据发送 | 原图、文字、包围框、候选译文中的哪些数据发给谁 |
| 服务请求 | 由哪台设备发起请求，调用哪个服务，使用哪套配置 |
| 结果连接 | 返回的结果接到哪个节点，或发布给哪些显示端 |
| 生命周期关系 | 哪些任务属于本次运行，停止或超时时影响哪些后续节点 |

### 5.2 跨设备通信经后台中转

不同设备之间的数据传递和服务调用，统一经过后台转发。同一台设备上的节点之间直接传递数据。

### 5.3 不同数据可以走不同路径

原图和文字可以分别发往不同的节点，每个服务只接收自己需要的数据。例如，翻译源只接收段落文字和语言设置，不接收原图。

下面是 4.3 中那条工作流的数据流向，归一化与竞速都在电脑 A 上完成：

```text
屏幕输入（电脑 A）→ OCR（电脑 A）→ 归一化（电脑 A）
  ├─ 包围框 → 显示输出：电脑 A 本机覆盖层
  ├─ 批次画面、包围框 → 经后台中转 → 显示输出：网页观看端
  ├─ 段落文字 → 翻译源 1：电脑 A 本机离线翻译 → 候选译文 → 竞速（电脑 A）
  └─ 段落文字 → 经后台中转 → 翻译源 2：后台 B 的 AI 翻译 → 候选译文 → 经后台中转 → 竞速（电脑 A）

竞速（电脑 A）
  ├─ 选中的译文 → 显示输出：电脑 A 本机覆盖层
  └─ 选中的译文 → 经后台中转 → 显示输出：网页观看端
```

本机覆盖层直接绘制在实时屏幕上，只接收包围框和译文；网页观看端还需要批次画面作为底图。

翻译源 2 的画布标注应当读作：由电脑 A 发起请求，经后台中转，调用后台 B 的 AI 翻译服务；发送段落文字、源语言和目标语言；返回该段落的候选译文。

## 6 持续屏幕的核心数据流

持续屏幕的默认数据流如下：

```text
Windows 屏幕输入 → 变化检测 → 批次画面 → OCR（只识别变化区域）→ 归一化 → 竞速翻译 → 结构化译文

结构化译文 → Windows 本机覆盖层
批次画面 + 结构化译文 → 网页显示
```

批次画面和结构化译文分开输出。结构化译文包含每个段落的标识、位置、当前选中的译文，以及它对应哪一张画面。网页显示把两者组合起来绘制，原画面本身不烧入译文；本机覆盖层直接绘制在实时屏幕上，只使用结构化译文。

只有进入批次的画面才发给网页显示。变化检测判定没有变化的截图留在源电脑上，不经后台转发。

## 7 一条工作流对应一份显示结果

同一条工作流在一次运行中只产生一份显示结果。所有显示端，包括 Windows 本机覆盖层和各个网页观看端，看到的是同一份竞速结果。显示设置由每个显示端各自保存，各端按自己的设置、屏幕尺寸和缩放比例绘制，规则见 [产品需求](01-product.md) 5.5。

新增一个观看端只是多订阅一份结果，不会额外触发 OCR 或翻译调用。

## 8 首版范围

首版只把 OCR、翻译、竞速等基础能力做成可调用的服务。一条工作流不能作为服务被另一条工作流调用；需要复用时，复制已有工作流或模板。
